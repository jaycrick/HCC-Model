## HCC Surveillance Markov Model: corrected calibration, refit of all bootstrap draws

Code for Cumming et al. 2024, *Cancers* 16(15):2745
(https://doi.org/10.3390/cancers16152745), with packages pinned by
`renv.lock`.

**Results match the publication: no.** This version corrects the calibration
(`CHANGES.md` G8: exact absorption probabilities) and replaces the optimiser
with a bounded one, then refits all 10,000 bootstrap resamples locally (G9).
The scenario point estimates match the paper. Several intervals and partial
correlations do not. See the Errata section of `README.md` at this tag and
`CHANGES.md` for the list.

### What the archive does not contain

The `.rds` files under `data-derived/` and `tests/testthat/fixtures/` are
stored in Git LFS, so this archive contains only small text pointer files in
their place. Three of them cannot be regenerated. The rest are regenerated by
the commands below.

### Regenerating the .rds files

From the root of the unpacked archive, with R 4.6 and the packages from
`renv.lock`:

```bash
# 1. Replace the LFS pointer files with the files that cannot be regenerated
cp <v1.0.0-published>/list_of_resampled_milton_output.rds data-derived/
cp <v1.0.0-published>/miltonoutput.rds data-derived/
cp <v1.3.0>/papers/2024-cancers/data-derived/param_names.rds data-derived/
shasum -a 256 data-derived/*.rds    # compare with the table above

# 2. Start from the pre-refit parameter CSVs (see below)
cp <v1.1.0>/data/Parameters.csv data/
cp <v1.1.0>/data/Parameters_25.csv data/

# 3. Install the pinned packages
Rscript -e 'renv::restore()'

# 4. Refit the point estimate and all 10,000 bootstrap resamples
Rscript tools/refit_calibration.R --cores 10

# 5. resampled_pars.rds, resampled_pars_fin.rds, and all figures
Rscript run_all.R --bootstrap

# 6. Test fixtures, then the tests
Rscript tests/testthat/fixtures/make_golden.R
Rscript tests/testthat/fixtures/make_ledger_baseline.R
Rscript -e 'testthat::test_dir("tests/testthat")'
```

Why step 2: in this version `tools/refit_calibration.R` starts its point fit
from the POINT column of `data/Parameters.csv`, and the same script rewrites
that file. The shipped files were produced from the pre-refit CSVs, which are
byte-identical to those at tag `v1.1.0`. Starting from this tag's own
(post-refit) CSVs moves 253 of 10,000 bootstrap fits by up to 2e-5 relative,
because near-tied optima flip (NLL unchanged to 1.1e-8). This is fixed after
v1.2.0: on `main` the start is the constant `PUBLISHED_MLE` in
`R/bootstrap.R` (`CHANGES.md` S13), bit-identical to the v1.1.0 CSV start, so
no CSV swap is needed there.

Step 4 writes `data/Parameters.csv`, `data/Parameters_25.csv`
and `data-derived/bootstrap_fit_diagnostics.rds`. It is deterministic: runs with
1, 9 and 10 cores and repeated runs gave bit-identical fits. It takes about
2.7 hours on 10 cores.
