## HCC Surveillance Markov Model: refactored, reproduces the publication

Refactored, documented and tested version of the code for Cumming et al. 2024,
*Cancers* 16(15):2745 (https://doi.org/10.3390/cancers16152745), with packages
pinned by `renv.lock`.

**Results match the publication: yes.** The test suite checks the published
values (abstract, Sec. 3, Table 3) at the printed precision. The fixes recorded
in `CHANGES.md` as G1-G7 change figures or labels, not the published numbers.

### What the archive does not contain

The `.rds` files under `data-derived/` and `tests/testthat/fixtures/` are
stored in Git LFS, so this archive contains only small text pointer files in
their place. Two of them cannot be regenerated, so download them from the
`v1.0.0-published` archive. The rest are regenerated by the commands below.

| File | Can be regenerated? | Get it from |
|------|---------------------|-------------|
| `data-derived/list_of_resampled_milton_output.rds` | No | `v1.0.0-published` archive (same bytes, SHA-256 `d04ea6ad…`) |
| `data-derived/miltonoutput.rds` | No | `v1.0.0-published` archive (same bytes, SHA-256 `005441da…`) |
| `data-derived/param_names.rds` | No (frozen published values; read only by the tests) | `v1.3.0` archive, `papers/2024-cancers/data-derived/param_names.rds` (same bytes, SHA-256 `2d38e9e5…`)\* |
| `data-derived/resampled_pars.rds` | Yes | step 3 |
| `data-derived/resampled_pars_fin.rds` | Yes | step 3 |
| `tests/testthat/fixtures/golden.rds` | Yes | step 4 |

\* The copy in `v1.0.0-published` holds the same 91 values, but they were
recomputed in the 2026 refactor and differ by up to 1.2e-12 relative. With
that copy, one ledger test (tolerance 1e-12) fails; the analysis does not
read the file.

### Regenerating the .rds files

From the root of the unpacked archive, with R 4.6 and the packages from
`renv.lock`:

```bash
# 1. Replace the LFS pointer files with the files that cannot be regenerated
cp <v1.0.0-published>/list_of_resampled_milton_output.rds data-derived/
cp <v1.0.0-published>/miltonoutput.rds data-derived/
cp <v1.3.0>/papers/2024-cancers/data-derived/param_names.rds data-derived/
shasum -a 256 data-derived/*.rds    # compare with the table above

# 2. Install the pinned packages
Rscript -e 'renv::restore()'

# 3. resampled_pars.rds (re-read from miltonoutput.rds) and
#    resampled_pars_fin.rds (scenario life-years, set.seed(315)); then all figures
Rscript run_all.R --bootstrap

# 4. Test fixture, then the tests
Rscript tests/testthat/fixtures/make_golden.R
Rscript -e 'testthat::test_dir("tests/testthat")'
```

**Checked on 2026-11-20** (macOS arm64, R 4.6.2, packages from `renv.lock`):
starting from only the three files that cannot be regenerated, steps 3-4
reproduced every `.rds` file:

| File | Result |
|------|--------|
| `resampled_pars.rds` | Identical values |
| `resampled_pars_fin.rds` | Parameter columns identical; life-year columns within 7.6e-16 relative (floating-point rounding on a different machine from the 2024 run); differences of nearly equal scenario columns within 2.6e-11 relative |
| `golden.rds` | Every entry identical (entry order differs) |

The test suite then passes (81 tests, 0 failures). The files are not
byte-identical (R's serialisation differs), so compare values, not checksums.
Time: step 3 took about 1 hour (`01_bootstrap_params.R` 8 min, the other
scripts about 50 min; this version predates the vectorised engine).
