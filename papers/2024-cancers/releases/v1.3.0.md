## HCC Surveillance Markov Model: per-paper layout, irreplaceable data in plain git

Code for Cumming et al. 2024, *Cancers* 16(15):2745
(https://doi.org/10.3390/cancers16152745), with packages pinned by
`renv.lock`.

**Results match the publication: no**, the same as `v1.2.0`. This release
does not change any number (`CHANGES.md` S12, S13): all tests pass and every
ledger value is byte-identical to `v1.2.0`. See the Errata section of
`papers/2024-cancers/README.md` for the differences from the paper.

### What changed

- Paper 1 now lives under `papers/2024-cancers/` (analysis scripts,
  `run_all.R`, `data/`, `data-derived/`). The shared model code stays in `R/`
  and finds a paper's files through `paper_path()`. This makes room for a
  second paper in the same repository.
- The three `.rds` files that cannot be regenerated
  (`list_of_resampled_milton_output.rds`, `miltonoutput.rds`,
  `param_names.rds`) are now plain git files, so this archive contains them.
  Same bytes as before (`param_names.rds` SHA-256 `2d38e9e5337b97e778038ea710db22ee60fa198442040a32b3cd4baf1cbf6d93`).
- The calibration refit's point fit now starts from fixed values
  (`PUBLISHED_MLE` in `R/bootstrap.R`) instead of the CSV it rewrites, so
  rerunning the refit is reproducible (S13).
- Version table in `README.md`; release notes for every tag in
  `papers/2024-cancers/releases/`.

### What the archive does not contain

The `.rds` files that can be regenerated are stored in Git LFS, so this
archive contains small text pointer files in their place:
`data-derived/resampled_pars.rds`, `bootstrap_fit_diagnostics.rds`,
`resampled_pars_fin.rds`, and `tests/testthat/fixtures/golden.rds`,
`ledger_baseline.rds`. A `git clone` followed by `git lfs pull` gets them.

To regenerate them from this archive, follow
[Regenerating the .rds files](https://github.com/jaycrick/HCC-Model/blob/v1.3.0/papers/2024-cancers/README.md#regenerating-the-rds-files)
in `papers/2024-cancers/README.md` (three steps; the refit takes about 2.7 h
on 10 cores). The result is byte-identical to the LFS files.
